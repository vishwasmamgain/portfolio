03. Projects

Multi-Asset Portfolio Management System

FINCART • Enterprise Fintech Platform

Java Spring Boot Kafka Redis

What It Does

Backend systems for a fintech platform managing Digital Gold, Mutual Funds, PMS, Unlisted Stocks, and Liquiloan. Integrated third-party MMTC-PAMP APIs for digital gold purchase/redemption, implemented FIFO-based portfolio accounting, and built scheduled cron jobs for daily portfolio valuations using live market prices.

Technical Approach

Event-driven architecture using Kafka for asynchronous transaction processing at 10,000+ transactions/day with retries, idempotency, and dead-letter queues. Complex multi-table SQL aggregation APIs power portfolio dashboards. Redis caching and SQL query optimization reduced backend latency by 30%.

Why FIFO Accounting?

FIFO (First-In-First-Out) was the right fit for accurate, auditable P&L calculation because it mirrors the actual chronological flow of transactions—when a user sells units, we need to realize gains/losses against the earliest purchased units first. This approach is not only compliant with standard accounting practices but also simplifies audit trails since each sell transaction deterministically maps to specific buy lots. Alternative methods like LIFO or weighted average would have obscured the true cost basis for sequential trades, making regulatory reporting and user-facing transaction histories harder to reconcile.

Key Achievement: 70% AI API Cost Reduction

Semantically similar queries were being sent to the LLM repeatedly—users asking "show my gold holdings" and "display gold portfolio" are functionally identical. By implementing Redis-based semantic caching with confidence-based request routing, we cached embeddings of previous queries and their responses. When a new query arrived, we computed its embedding and checked similarity against cached entries. If confidence exceeded a threshold, we served from cache instead of calling the LLM. This cut redundant API calls by 70% while maintaining response quality.

AI-Powered Job Tracker

Personal Project • Full-Stack Application

Java Spring Boot Spring AI Docker

What It Does

End-to-end job application tracker with natural language search capabilities. Users can track applications, add notes, and search using conversational queries like "show me rejected jobs from last month" or "find all interviews scheduled this week."

Technical Approach

Built with Java, Spring Boot, PostgreSQL, Redis, Spring AI, JWT authentication, and Docker Compose. Integrated Spring AI with Groq's LLM API to enable natural language search over structured job application data. Implemented Redis caching with TTL-based invalidation for frequently accessed queries. Fully containerized for one-command local deployment.

Key Decision: Semantic Search Over Structured Data

Instead of building complex SQL query parsers for natural language input, I leveraged Spring AI to convert user queries into embeddings and match them against pre-computed embeddings of job records. This approach handles synonyms, typos, and varied phrasing naturally—"rejected" matches "denied," "not selected," etc.—without maintaining exhaustive synonym lists or regex patterns.

AI-Powered Transaction Classification Platform

Enterprise System • Event-Driven Architecture

Kafka Spring AI Redis GPT API

What It Does

Event-driven backend for automated fintech transaction classification, processing 10,000+ transactions/day. Automatically categorizes incoming transactions (merchant type, expense category, tax implications) using AI models with human-in-the-loop fallback for low-confidence predictions.

Technical Approach

Kafka consumers process transaction events asynchronously. Each transaction flows through a classification pipeline: rule-based pre-filtering → semantic cache lookup → LLM classification (if needed) → confidence routing → persistence. Implemented retries, idempotent consumers, and dead-letter queues for reliability.

Key Achievement: Reliability at Scale

The system handles 10,000+ transactions daily with 99.9% uptime. Idempotent consumers ensure exactly-once processing semantics even when Kafka redelivers messages. Dead-letter queues capture failed classifications for manual review, preventing data loss while allowing the pipeline to continue processing. This design choice prioritized data integrity over raw throughput—a critical requirement for financial systems.
